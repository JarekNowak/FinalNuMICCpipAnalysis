PeLEE ntuples of the NuMI pion analyses: ours against /data/uboone/temp/custom_pelee_ntuples
=========================================================================================
2026-10-23

Compared: the inputs of our chain (slurm/mp2pi_2f_manifest.list, slurm/beamon_skim_manifest.list on multipion/kin;
the same files feed the single-pion releases) and the custom PeLEE ntuples in
  /data/uboone/temp/custom_pelee_ntuples             (prod_v08_00_00_73 numi_pion_pelee_ntuple_nu_overlay_ppfxfixes,
                                                      prod_v08_00_00_67 numi_pion_pelee_ntuple_dirt_overlay, ...)
  /data/uboone/temp/reweighted_custom_pelee_ntuples  (the nu and nue overlays reweighted to the new NuMI flux)
Tools: report/tools/pelee_compare.py (30 pairs; --reweighted for the 8 overlay pairs against the reweighted files),
report/tools/pelee_compare_rates.py (true CC rates per POT). Output: report/planning/pelee_compare.json,
pelee_compare_reweighted.json, pelee_compare_rates.json.
Per pair: entries, subruns and summed POT, branch sets, weight vector lengths, the overlap of (run, subrun) and
(run, subrun, event), duplicates, and for the common events the agreement of nslice, topological_score,
reco_nu_vtx_x/z, n_tracks, n_showers, CosmicIP, ppfx_cv, weightSplineTimesTune, nu_e and nu_pdg.
Beam-on POT and triggers are not stored in the files, so the data exposures are not compared here.


1. Summary
----------
a) Overlays, Runs 1-4: different productions. Ours are the new-flux generations (/data/uboone/new_numi_flux), the
   custom ones are the old-flux ppfxfixes production. Events that share (run, subrun, event) are different neutrinos
   (nu_e identical for 0.004%). The raw custom overlays are on the old flux: per POT they carry 19% (FHC nu_mu) to
   44% (RHC nu_mu) more true CC than ours. The reweighted custom overlays agree with ours in rate to about 1%.
b) The reweighted custom overlays are an accept/reject resampling of the raw ones: same POT, 27% fewer events
   (run1_fhc: 872525 -> 635056; the dropped events have mean E_nu 1.77 GeV against 1.49 kept), ppfx_cv replaced.
   Our Run-5 FHC overlay is this reweighted file (identical event by event, all variables).
c) Wrong-sign and RHC spectra: equal rates, different mean energies between the new-flux generations (ours, Runs 1-4)
   and the reweighted samples (custom, and our own Run 5): FHC nu_mu-bar 1.91-1.93 against 2.04-2.06 GeV, RHC
   nu_mu-bar 1.62 against 1.73-1.75 GeV, RHC nu_mu 1.77 against 1.80-1.81 GeV. Our FHC configuration mixes the two
   kinds (Run 5 reweighted, Runs 1, 2, 4 generated). FHC nu_mu agrees (1.48-1.49 GeV).
d) Data (beam-on, beam-off) and dirt: the same events. Every compared variable is identical for every common event
   (dirt Run 4b: 99.9%). The differences are in the event lists (good-run selections, extra subruns) and branches.
e) Run 4c: the custom production splits Run 4c at run 21410 and labels runs 21286-21410 RHC (beam_on/splitFile_run4c.cxx,
   numi_beam_on_pion_ntuples_run4c_{fhc,rhc}.root). Our Run-4c beam-on file contains these runs (11.7% of its events,
   11% of its subruns) and is used as FHC (beamon_fhc_run4c in the skim manifest; the FHC Run-4 POT 2.075e20). Our
   Run-4c dirt starts at run 21411, and we use a Run4c_rhc overlay in the RHC configuration, both consistent with the
   custom split. Our beam-off Run 4c also contains runs 21286-21410 (EXT is mode independent, so no issue there).
   To check before unblinding: the horn polarity of runs 21286-21410 and whether the FHC Run-4 POT includes them.
f) Branches: the custom Run 1 and Run 3b data and dirt carry 41 (data) / 52 (dirt) branches our old productions lack,
   among them trk_bragg_pion_v (+ _u_v, _v_v), trk_trunk_dEdx_{u,v,y}_v, trk_nhits_{u,v,y}_v, trk_end_spacepoints_v,
   shr_energy_second/third, interaction_time_abs/modulo, the cosmic_*_v and nu_center* blocks. These are the branches
   whose absence makes the released Bragg cut fail open in Run 1-3 data (old-production-missing-branches). In
   Runs 4-5 the reverse holds: ours carry 33 branches the custom files lack, among them trk_avg_deflection_*_v (the
   wiggliness used for the golden pions), trk_bragg_{mu,p,pion}_{fwd_preferred,alt_dir}_*, trk_trunk_rr_dEdx_*_v,
   pfp_vtx_*_v, slice_topo_score_v, slice_id.
g) Weight vectors: same lengths everywhere (weightsPPFX 600, weightsGenie 600, weightsReint 1000) except the custom
   Run-1 FHC dirt slim file, which has no weightsReint (length 0) and no weightsFlux, and our Run-1 FHC dirt, which
   has weightsFlux 1000.

7. Points that bear on our analyses
-----------------------------------
- Run 4c polarity (1e): the one difference that could change a result at unblinding. If runs 21286-21410 are RHC,
  11.7% of the Run-4c beam-on events (about 1% of the FHC beam-on) sit in the FHC sample with no FHC simulation
  behind them, and the FHC Run-4 POT has to be checked for the same runs.
- Mixed flux treatments within a configuration (1c): FHC Run 5 is reweighted while FHC Runs 1, 2, 4 are new-flux
  generations; rates agree, wrong-sign mean energies differ by 7%. The same holds for the RHC samples if a
  reweighted file is ever added.
- Missing Bragg branches in Run 1-3 data (1f): the custom Run 1 and 3b beam-on, beam-off and dirt files carry
  trk_bragg_pion_v and the trunk dE/dx and per-plane hit branches. They are a candidate replacement for our old
  productions (same events, identical reconstruction otherwise), which would remove the fail-open of the Bragg cut;
  they lack the Run 4-5 deflection and fwd/alt Bragg branches, which our Run 1-3 files also lack.
- The custom area holds Run 1-3 detector variations and Run 2 data that we do not have.
- Raw custom overlays must not be used without the flux reweighting (19-44% rate excess).
